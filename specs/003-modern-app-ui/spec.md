## Clarifications

### Session 2026-08-22

- Q: AI 서빙 UI 참조 앵커를 어느 결로 재현하는가? → A: **Linear 스타일**. 절제된 여백, 얇은 보더 중심 위계, 목록·리스트의 정보 밀도 높음, 명확한 활성 상태(subtle background pill/highlight), keyboard-first 뉘앙스의 절제된 UI. Claude/ChatGPT의 채팅 캔버스 정서나 Cursor의 IDE 밀도, Vercel의 대시보드 톤은 이 스펙에서 채택하지 않는다.
- Q: BM 한나체(디스플레이 폰트)를 어디까지 사용하는가? → A: **완전 폐기**. 헤드라인·본문·UI 모두 Pretendard 단일 스택. 002에서 추가한 한나체 CDN 링크(BMHANNAPro)와 `--font-display` 변수는 이 스펙에서 제거하며, 헤드라인은 weight·크기로만 위계를 표현한다.
- Q: 페이지 전환 애니메이션의 구체적 형태는? → A: **Fade + 6px 수직 슬라이드**(아래→위). 총 지속 200ms, ease-out. 라우트 방향 무관하게 동일한 전환. `prefers-reduced-motion: reduce`에서는 즉시 전환으로 대체.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모던 미니멀 디자인 시스템 재구축 (Priority: P1)

기존의 색·타이포·컴포넌트 스타일을 전부 폐기하고, **Linear 스타일의 절제된 시각 언어**로 재구축한다. 얇은 보더(1px) 중심의 위계, 서브틀한 배경 하이라이트로 표현하는 활성 상태, 목록·리스트의 정보 밀도가 높으면서도 여백이 정돈된 톤이 기본이다. 브랜드 색은 한 개만 억제되게 사용되며, 무거운 그림자·화려한 강조·헤비 디스플레이 폰트는 사용하지 않는다. 좌측 접이식 사이드바 레이아웃은 유지된다. [DESIGN.md](../../DESIGN.md)의 토큰(색·간격·라운드)은 참조로 사용하되, 배민 특유의 놀이감·손그림·풀블리드 컬러 어휘는 채택하지 않는다.

**Why this priority**: 사용자가 앱을 다시 열고 싶게 만드는 시각적 첫인상. 이 시스템이 확정되지 않으면 뒤이어 오는 인터랙션·마이크로 UI 결정을 매번 임시로 처리해야 한다.

**Independent Test**: 앱을 로그인 상태로 열고 4개 대표 화면(내 문제집 목록 · 문제집 상세 · 학습 모드 · 프로필)을 순회하며, (a) 총 사용된 브랜드 강조 색이 한 종류 이하, (b) 각 화면 여백 비중이 콘텐츠보다 크거나 같음, (c) 무거운 그림자/그라디언트/화려한 카드가 없음, (d) 좌측 사이드바 여전히 존재 · 접기 가능을 시각적으로 확인.

**Acceptance Scenarios**:

1. **Given** 로그인된 사용자가 임의의 페이지에 있을 때, **When** 좌측 사이드바를 보면, **Then** 사이드바는 지금과 동일하게 좌측 고정 + 접기 가능하며, 시각적으로는 새 디자인 시스템의 톤(절제된 색·미니멀한 아이콘·명확한 활성 상태)으로 렌더된다.
2. **Given** 어느 화면이든, **When** 디자인 시스템 검사를 하면, **Then** 브랜드 강조 색은 하나만 사용되고, 나머지 색은 회색 스케일 안에서 위계를 표현한다.
3. **Given** 카드·리스트·버튼·인풋 등 재사용 컴포넌트를 볼 때, **When** 시각적 결을 확인하면, **Then** 두꺼운 보더·크고 진한 그림자·과장된 라운드가 없고, 대부분 얇은 보더(1px) 또는 배경색 차이로만 위계를 표현한다.
4. **Given** 텍스트가 많은 화면(문제집 상세, 학습 모드 카드)을 볼 때, **When** 스크롤 없이 첫 화면을 보면, **Then** 여백이 넉넉해 시선이 콘텐츠에 자연스럽게 머문다 (한 화면에 세 개 이상의 강조 요소가 동시에 시선을 다투지 않음).
5. **Given** 학습 모드 화면을 열 때, **When** 문제 카드를 보면, **Then** 카드는 콘텐츠(제목·본문·키워드)를 담는 얇은 컨테이너 톤이며, 배경 대비 미묘한 표면 차이·최소한의 그림자만 사용한다.
6. **Given** 폼 화면(로그인·회원가입·문제집·문제)을 볼 때, **When** 입력 필드를 보면, **Then** 필드는 얇은 보더 또는 서브틀 배경 하나로 구분되고, 포커스 시에는 브랜드 색의 얇은 링(ring) 또는 강한 보더로 명확히 반응한다.

### User Story 2 - 앱 수준의 자연스러운 인터랙션 (Priority: P1)

웹 앱이지만 네이티브 앱을 만지는 감각을 준다. 페이지를 이동할 때 딱딱한 리로드감 대신 자연스러운 전환 애니메이션이 붙고, 스크롤은 관성 있게 부드럽게 흐르며, 버튼·카드·사이드바 등 모든 상호작용 요소가 미묘한 피드백(누르는 순간의 눌림감, hover 시의 색 변화, 완료 시의 페이드)으로 반응한다. 학습 모드에서 문제를 넘길 때도 즉시 튕겨나오지 않고 살짝 슬라이드되며 다음 문제가 나타난다.

**Why this priority**: 시각적 톤(US1)이 갖춰져도 인터랙션이 딱딱하면 여전히 "웹페이지" 감각이 남는다. 앱 느낌의 마감이 있어야 사용자가 실제로 매일 학습 도구로 켜게 된다.

**Independent Test**: 모바일 뷰포트(375×667)에서 로그인 → 내 문제집 목록 → 문제집 상세 → 학습 모드 시작 → 세 번 다음 → 목록으로 나가기 순서로 진행하며, (a) 각 라우팅 전환에 200~300ms 전환 애니메이션(fade + subtle slide)이 있음, (b) 스크롤이 관성 있고 매끄러움, (c) 모든 탭·클릭 지점이 눌림 순간 미묘한 스케일 다운·색 변화 반응, (d) 학습 카드의 다음 문제 전환이 즉시 컷아웃 아님을 확인.

**Acceptance Scenarios**:

1. **Given** 사용자가 임의의 화면에서 다른 페이지로 이동할 때, **When** 라우팅이 발생하면, **Then** 새 페이지는 100~300ms 사이의 전환 애니메이션(fade + 부드러운 수직 슬라이드 4~8px 정도)으로 나타난다. 새로고침 같은 딱딱한 컷아웃 없음.
2. **Given** 사용자가 콘텐츠가 긴 페이지를 볼 때, **When** 스크롤을 시작하면, **Then** 스크롤은 CSS smooth scroll 또는 브라우저 관성 스크롤로 매끄럽게 흐르고, 앵커·"위로 가기" 같은 이동도 즉시 점프가 아니라 애니메이션으로 이동한다.
3. **Given** 어느 상호작용 요소(버튼·링크·카드·사이드바 아이템)든, **When** 마우스 hover 또는 터치 tap 순간, **Then** 그 요소는 미묘한 피드백을 준다: hover는 배경/색 변화(≤120ms), tap은 순간적인 스케일 다운(scale 0.97~0.99).
4. **Given** 학습 모드에서 문제를 보고 있을 때, **When** "다음" 버튼을 누르면, **Then** 현재 문제 카드가 짧게 페이드아웃하며 다음 문제 카드가 페이드인한다 (총 ≤250ms). 즉시 컷아웃 아님.
5. **Given** 사이드바를 접거나 펼칠 때, **When** 토글 버튼을 누르면, **Then** 사이드바 너비와 콘텐츠 영역 여백이 동시에 부드럽게 전환된다(200ms). 텍스트 라벨은 페이드로 나타나거나 사라진다.
6. **Given** 어떤 액션이 서버 응답을 기다릴 때(폼 제출, 데이터 조회), **When** 지각 지연이 300ms 이상이면, **Then** 스켈레톤 또는 서브틀한 스피너로 진행 중임을 알린다. 화면이 얼어붙지 않음.
7. **Given** 모바일 사용자가 사이드바 drawer를 열었을 때, **When** 뒤 배경(backdrop)을 탭하거나 나열된 항목을 누르면, **Then** drawer가 부드럽게 슬라이드아웃되며 닫힌다 (딱딱한 즉시 사라짐 아님).

### Edge Cases

- **애니메이션 감속 선호 사용자(prefers-reduced-motion: reduce)**: 애니메이션은 자동으로 즉시 전환으로 대체된다 (접근성 표준 준수).
- **저성능 기기**: 스크롤 애니메이션·페이지 전환이 프레임 드롭 없이 부드럽게 유지되지 않을 수 있음. 최소한 애니메이션이 있어야 할 자리에 CSS 폴백이 있어야 함(자바스크립트가 로드 전이어도 기본 렌더는 정상).
- **폰트 로딩 실패**: FOUT 짧게 발생 후 시스템 폰트로 폴백. 이 스펙에서 새로 추가되는 폰트 관련 이슈는 없음(기존 CDN 유지).
- **매우 넓은 화면(1920px+)**: 콘텐츠 폭이 지나치게 길게 흐르지 않도록 max-width 유지. 사이드바 옆 남는 공간은 배경으로 자연스럽게 흡수.
- **매우 좁은 화면(320px)**: 사이드바 drawer가 화면 폭의 대부분을 차지하되, 열림 시 여전히 백드롭 영역 일부를 탭해 닫을 수 있어야 함.
- **모바일에서 인풋 포커스 시 확대(iOS Safari)**: viewport meta의 initial-scale=1과 인풋 font-size ≥16px로 자동 확대 방지.

## Requirements *(mandatory)*

### Functional Requirements

**레이아웃 (US1)**

- **FR-301**: 기존(002 스펙 기준)의 배민 스타일 UI는 이 스펙 배포 이후 앱에서 렌더되지 않아야 한다 (모든 페이지가 새 디자인 시스템으로 다시 그려진다).
- **FR-302**: 좌측 접이식 사이드바 레이아웃은 그대로 유지된다 (직전 요구 사항이었던 사이드바 자체는 폐기 대상이 아님).
- **FR-303**: 콘텐츠 영역은 중앙 정렬되고 최대 폭 제한이 있어, 매우 넓은 화면에서도 텍스트가 지나치게 길게 흐르지 않아야 한다.
- **FR-304**: footer 영역은 이 스펙에서도 렌더되지 않는다 (기존 규칙 유지).
- **FR-305**: 상단 nav 바(TopNav 등)는 데스크톱에서 렌더되지 않는다 (사이드바가 유일한 주요 내비게이션).

**디자인 시스템 (US1)**

- **FR-306**: 앱 전체가 사용하는 브랜드 강조 색은 정확히 한 종류다 (색 값 자체는 [DESIGN.md](../../DESIGN.md)의 primary mint에서 파생하되, 사용 빈도는 배민 대비 훨씬 줄인다).
- **FR-307**: 나머지 색은 회색 스케일(near-black · dark gray · mid gray · light gray · near-white)만으로 위계를 표현한다.
- **FR-308**: 앱 전체 본문·UI·헤드라인은 정확히 하나의 sans-serif 계열(Pretendard)만 사용한다. 002에서 도입한 디스플레이 폰트(BM 한나체)는 CDN 링크와 CSS 변수까지 완전히 제거하며, 헤드라인의 위계는 weight(700/800/900)와 크기·자간만으로 표현한다.
- **FR-309**: 그림자는 최소한만 사용하고(≤ 2 레벨), 대부분의 위계는 배경 색 차이와 얇은 보더(1px)로 표현한다.
- **FR-310**: 라운드는 [DESIGN.md](../../DESIGN.md)의 스케일 안에서 절제되게 사용하며, 알약(pill) 형태의 큰 라운드는 특정 컴포넌트(주요 버튼·태그)로 제한한다.
- **FR-311**: 간격은 [DESIGN.md](../../DESIGN.md)의 4px 베이스 스케일을 그대로 채택한다.
- **FR-312**: 아이콘은 얇은 라인(stroke) 스타일로 통일되고 stroke-width가 화면 전반에서 일관된다.

**인터랙션·애니메이션 (US2)**

- **FR-313**: 라우트 이동 시 페이지 전환 애니메이션이 있어야 하며, 구체 사양은 **fade + 6px 수직 슬라이드**(콘텐츠가 아래에서 위로 이동하며 페이드인), 총 지속 200ms, ease-out. 라우트 방향(더 깊은 경로 vs 상위 경로)에 무관하게 동일한 전환이 적용된다.
- **FR-314**: 페이지 스크롤은 브라우저 기본 스크롤을 넘어, "위로 이동"·앵커 링크 등 프로그램적 스크롤 시 부드러운 스크롤 애니메이션이 적용된다.
- **FR-315**: 모든 상호작용 요소(버튼·링크·카드·사이드바 항목)는 hover 시 배경/색 변화(≤120ms), 활성화(tap/click) 시 미묘한 스케일 다운(0.97~0.99, ≤120ms)의 피드백을 준다.
- **FR-316**: 학습·암기 모드의 문제 카드 전환은 즉시 컷아웃이 아니라 페이드아웃 → 페이드인 시퀀스(총 ≤250ms)로 처리된다.
- **FR-317**: 좌측 사이드바 접기·펼치기는 200ms 이내의 폭 전환 애니메이션으로 이루어지고, 라벨 텍스트는 페이드로 나타나거나 사라진다.
- **FR-318**: 모바일 사이드바 drawer는 슬라이드인·슬라이드아웃 애니메이션(200ms 이내)으로 열리고 닫힌다. 백드롭 페이드가 동반된다.
- **FR-319**: 지각 지연이 300ms 이상 예상되는 서버 상호작용(폼 제출·데이터 조회 등)에는 스켈레톤 또는 서브틀한 스피너 등 진행 상태 표시가 있어야 한다.
- **FR-320**: `prefers-reduced-motion: reduce`가 설정된 사용자에게는 모든 애니메이션이 즉시 전환으로 대체된다 (접근성 준수).

**모바일 특화 (US1 + US2)**

- **FR-321**: 모든 인터랙티브 요소의 터치 영역은 최소 44×44 CSS 픽셀 이상이어야 한다.
- **FR-322**: 모바일에서 인풋 포커스 시 자동 확대되지 않아야 한다 (iOS Safari 대응).
- **FR-323**: 안전 영역(safe-area) 여백을 확보해 노치·홈 인디케이터와 겹치지 않는다.

**범위 제한**

- **FR-324**: 이 스펙 범위에서 다크 모드는 지원하지 않는다 (라이트 모드만).
- **FR-325**: 002 스펙의 승인제·인증·데이터 접근 관련 FR은 그대로 유효하며, 이 스펙에서 변경되지 않는다.

### Key Entities

- **디자인 토큰(Design Token)** — [DESIGN.md](../../DESIGN.md)에서 참조한 색·간격·라운드·엘리베이션·애니메이션 값의 집합. 이 스펙은 그중 절제된 하위 집합만 채택한다 (배민 특유의 정서적 요소는 제외).
- **모션 프로파일(Motion Profile)** — 페이지 전환·마이크로 인터랙션·사이드바 애니메이션의 지속 시간과 이징 함수 표준.
- **뷰포트 프로파일(Viewport Profile)** — 두 축: 모바일(≤ 640px)과 데스크톱(≥ 641px). 002 스펙 정의 그대로 유지.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-301**: 페이지 전환 애니메이션은 정확히 200ms 지속 (fade + 6px 수직 슬라이드, ease-out); DevTools Performance 탭에서 측정 시 오차 ±30ms 이내.
- **SC-302**: 사이드바 접기·펼치기 애니메이션이 200ms 이내에 완료된다.
- **SC-303**: 학습 모드의 "다음"·"이전" 액션 이후 다음 카드가 완전히 표시되기까지 걸리는 총 지각 시간이 250ms 이내이다.
- **SC-304**: 로그인 이후 접근하는 모든 페이지의 모든 클릭·탭 가능 요소(버튼·링크·카드·사이드바 항목)에 hover 또는 active 시각 피드백이 있다 (100% 준수).
- **SC-305**: 화면 전체에서 브랜드 강조 색으로 인식되는 색상 종류의 수 = 1 (회색 스케일 이외).
- **SC-306**: 모바일 뷰포트에서 인터랙티브 요소 중 44×44 CSS 픽셀 미만인 것 = 0.
- **SC-307**: 라우트 이동 시 눈에 띄는 콘텐츠 레이아웃 시프트(CLS 지표) = 0.05 이하.
- **SC-308**: `prefers-reduced-motion: reduce` 사용자의 브라우저에서 확인 시 페이지 전환·마이크로 애니메이션이 즉시 전환으로 대체되었음을 검사할 수 있다 (100% 준수).
- **SC-309**: 초기 방문 시 필수 폰트·CSS·JS 총 다운로드(gzip) 500KB 이하 유지 (002 기준 유지, 새 애니메이션 라이브러리 도입으로도 초과하지 않음).

## Assumptions

- **네이티브 앱은 이 스펙 범위 밖이다.** "웹/앱 양측 고려"는 반응형 웹앱이 모바일 브라우저에서도 앱과 유사한 감각을 준다는 뜻이다. iOS/Android 애플리케이션은 포함하지 않는다.
- **좌측 접이식 사이드바 아키텍처는 유지된다** (직전 대화에서 사용자가 명시적으로 선호). 이번 스펙은 사이드바의 시각·인터랙션을 다듬는 방향이지 완전히 재설계하는 것이 아니다.
- **002 스펙의 승인제·인증·데이터 접근·RLS 규칙은 이 스펙에서 변경되지 않는다.** 어떤 라우트가 어떤 조건에서 접근 가능한지는 002에 정의된 규칙을 그대로 승계.
- **다크 모드는 이 스펙 범위 밖이다.** 라이트 모드만 지원. 브라우저 `prefers-color-scheme` 감지도 하지 않는다.
- **국제화·다국어는 범위 밖이다.** 한국어 단일 언어.
- **완전한 접근성 인증(WCAG AA 검사 통과)은 목표로 하지 않으나**, `prefers-reduced-motion` 대응과 44px 터치 영역, 색 대비 최소 준수 정도는 지킨다.
- **[DESIGN.md](../../DESIGN.md)는 토큰의 출처일 뿐 스타일 지침의 전체가 아니다.** 배민 특유의 두꺼운 손그림 윤곽선·풀블리드 강조 색·놀이감 있는 캐릭터·헤비 디스플레이 폰트의 광범위 사용은 이 스펙에서 채택하지 않는다.
- **애니메이션 라이브러리(예: framer-motion)의 도입 여부는 스펙 범위 밖(구현 결정)이다.** 다만 이 스펙의 성능·번들 제약(SC-309)을 지키는 선에서만 허용된다.
