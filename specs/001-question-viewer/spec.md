# Feature Specification: 면접 준비 문제 조회 (Question Viewer MVP)

**Feature Branch**: `001-question-viewer`

**Created**: 2026-08-21

**Status**: Draft

**Input**: User description: "면접 준비 프로젝트. (1) 아이디/비밀번호 기반 회원가입·로그인·로그아웃, (2) 문제집–문제 1:N 관계와 문제집의 공개/비공개 구분(로그인 필수), (3) 문제는 제목·내용·키워드로 구성, (4) 학습 모드(모두 표시) / 암기 모드(제목만 표시 후 버튼으로 내용·키워드 공개), (5) 문제들을 순서대로 하나씩 조회. 초기 MVP 범위는 순서대로 조회하는 것에 집중, 이어서 하기 기능 없음, footer 없음."

## Clarifications

### Session 2026-08-21

- Q: 문제 이동 방향은 "다음"만 지원하는가, "다음/이전" 모두 지원하는가? → A: 다음/이전 모두 지원. 첫 문제에서는 "이전"이 비활성, 암기 모드에서 이전 문제로 이동하면 그 문제도 내용/키워드가 다시 숨겨진 상태로 초기화된다.
- Q: 키워드는 어떤 형태로 입력·저장하는가? → A: 문자열 배열로 저장. 입력 시 콤마 또는 엔터로 자동 분리하고 뱃지(chip) 형태로 표시. 입력 순서를 유지하고, 같은 문제 안의 중복 키워드는 저장 전에 제거한다.
- Q: 문제집/문제의 편집·삭제를 허용하는가? → A: 허용. 소유자에 한해 문제집(제목·공개 여부)과 문제(제목·내용·키워드) 모든 필드를 편집 가능하고, 문제집·문제 모두 삭제 가능하다. 문제집 삭제 시 소속 문제도 함께 사라진다. 다른 사용자의 공개 문제집은 여전히 조회만 가능. (기존 FR-026은 폐기)
- Q: 학습 모드와 암기 모드는 문제집 조회 중에 전환할 수 있는가? → A: 전환 불가. 모드는 문제집을 여는 시점에만 선택하고, 순회 중에는 바꿀 수 없다. 모드를 바꾸려면 문제집 목록으로 돌아가 다시 열어야 한다.
- Q: "학습 완료" 화면에서 어떤 액션을 제공하는가? → A: 완료 문구("학습 완료했습니다" 등)만 표시하고 별도의 액션 버튼(다시 학습·목록으로 등)은 두지 않는다. 사용자는 브라우저 뒤로 가기나 상단 네비게이션으로 직접 이동한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 문제집을 순서대로 학습/암기 (Priority: P1) 🎯 MVP

로그인한 사용자가 문제집(자신의 것 또는 다른 사람의 공개 문제집)을 열어 문제를 하나씩 순서대로 넘겨보며 학습한다. 학습 모드에서는 제목·내용·키워드가 처음부터 다 보이고, 암기 모드에서는 제목만 먼저 보였다가 "내용 보기" 액션을 하면 내용과 키워드가 드러난다.

**Why this priority**: 사용자가 이 앱을 실제로 여는 유일한 이유. 이 하나만 되어도 면접 준비 도구로서의 최소 가치가 성립한다.

**Independent Test**: 시드로 계정 하나와 문제집 하나(문제 여러 개 포함)를 미리 넣어두고, 로그인 → 문제집 열기 → 첫 문제 표시 → "다음" 반복 → 마지막 문제 → 완료 상태까지 진행. 학습 모드와 암기 모드 각각에서 검증.

**Acceptance Scenarios**:

1. **Given** 로그인된 상태이고 문제 3개짜리 문제집을 학습 모드로 열었을 때, **When** 첫 문제가 표시되면, **Then** 제목·내용·키워드가 모두 처음부터 함께 보인다.
2. **Given** 로그인된 상태이고 문제 3개짜리 문제집을 암기 모드로 열었을 때, **When** 첫 문제가 표시되면, **Then** 제목만 보이고 내용과 키워드는 숨겨져 있다.
3. **Given** 암기 모드로 문제를 보고 있을 때, **When** "내용 보기" 버튼을 누르면, **Then** 해당 문제의 내용과 키워드가 나타난다.
4. **Given** 문제집의 N번째 문제(N < 총 문제 수)를 보고 있을 때, **When** "다음"을 선택하면, **Then** (N+1)번째 문제가 표시되고, 암기 모드라면 다시 제목만 보이는 상태에서 시작한다.
5. **Given** 문제집의 마지막 문제를 보고 있을 때, **When** "다음"을 선택하면, **Then** "학습 완료" 상태가 표시되고 첫 문제로 순환하지 않는다.
6. **Given** 로그인되지 않은 상태에서, **When** 문제집 URL에 직접 접근하면, **Then** 로그인 화면으로 이동한다.

### User Story 2 - 아이디/비밀번호 계정 (Priority: P2)

사용자는 아이디와 비밀번호로 회원가입하고 로그인/로그아웃 할 수 있다. 다른 인증 수단(OAuth, 이메일 인증, SMS 등)은 사용하지 않는다.

**Why this priority**: 문제집의 소유권과 공개/비공개 구분이 성립하려면 계정 개념이 필요하다. 다만 US1은 시드 데이터로도 독립 테스트가 가능하기 때문에 우선순위는 P1이 아닌 P2.

**Independent Test**: 신규 아이디로 회원가입 → 자동 로그인 확인 → 로그아웃 → 같은 아이디로 재로그인 → 상단 UI가 로그인 상태로 바뀜 확인.

**Acceptance Scenarios**:

1. **Given** 비로그인 상태에서 회원가입 화면에 있을 때, **When** 사용 가능한 아이디와 유효한 비밀번호로 가입하면, **Then** 계정이 생성되고 자동 로그인 상태가 된다.
2. **Given** 이미 사용 중인 아이디로 회원가입을 시도할 때, **When** 폼을 제출하면, **Then** "이미 사용 중인 아이디" 오류가 표시되고 계정은 생성되지 않는다.
3. **Given** 계정이 있는 사용자가 로그인 화면에 있을 때, **When** 올바른 아이디/비밀번호를 입력하면, **Then** 로그인되고 홈으로 이동한다.
4. **Given** 로그인된 사용자가 로그아웃을 실행하면, **When** 요청이 처리되면, **Then** 세션이 종료되고 비로그인 상태 UI로 돌아간다.
5. **Given** 잘못된 비밀번호로 로그인을 시도할 때, **When** 폼을 제출하면, **Then** "아이디 또는 비밀번호가 올바르지 않습니다"라는 통합 오류가 표시된다 (어느 필드가 틀렸는지는 노출하지 않음).

### User Story 3 - 문제집/문제 만들기 · 편집 · 삭제 (Priority: P2)

로그인한 사용자가 자신의 문제집과 문제를 생성·수정·삭제한다. 문제집에는 제목과 공개 여부를 지정하고, 그 안에 문제(제목·내용·키워드들)를 추가하며, 필요할 때 각 필드를 수정하거나 문제집·문제를 삭제한다.

**Why this priority**: 사용자가 자기 데이터를 만들고 유지 관리할 수 있어야 앱이 실제로 쓸모 있어진다. 다만 US1을 시드 데이터로 검증할 수 있으므로 MVP 이후 순위.

**Independent Test**: 로그인 → 새 문제집 생성(제목, 공개 여부) → 문제 3개 추가 → 그중 하나의 내용과 키워드 수정 → 다른 하나 삭제 → 문제집 공개 여부 토글 → 마지막에 문제집 자체 삭제 → 문제집 목록에서 사라졌는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인된 사용자가 새 문제집 만들기 화면에 있을 때, **When** 문제집 제목과 공개 여부를 입력하고 저장하면, **Then** 문제집이 생성되어 그 사용자의 문제집 목록에 나타난다.
2. **Given** 자신의 문제집을 열었을 때, **When** "문제 추가"로 제목·내용·키워드(0개 이상)를 입력하고 저장하면, **Then** 새 문제가 문제집의 마지막 위치에 추가된다.
3. **Given** 사용자 A의 비공개 문제집이 있을 때, **When** 사용자 B가 그 문제집 URL로 접근하면, **Then** 접근이 거부된다 (문제집이 없는 것처럼 보이거나 권한 오류).
4. **Given** 내 문제집 목록에 여러 개의 문제집이 있을 때, **When** 사용자가 하나를 선택하면, **Then** 해당 문제집의 문제들이 추가된 순서대로 표시된다.
5. **Given** 자신의 문제집을 열었을 때, **When** 문제집 제목이나 공개 여부를 수정하고 저장하면, **Then** 변경 사항이 즉시 반영되고 다음 조회부터 새 값이 적용된다.
6. **Given** 자신의 문제집에 속한 문제를 열었을 때, **When** 제목·내용·키워드 중 어느 것이든 수정하고 저장하면, **Then** 변경 사항이 즉시 반영된다.
7. **Given** 자신의 문제집에 여러 문제가 있을 때, **When** 그중 하나를 삭제하면, **Then** 해당 문제만 사라지고 나머지 문제의 상대 순서는 유지된다.
8. **Given** 자신의 문제집을 삭제하면, **When** 목록을 다시 확인하면, **Then** 해당 문제집과 그 안의 모든 문제가 함께 사라져 있다.
9. **Given** 사용자 A의 공개 문제집을 사용자 B가 보고 있을 때, **When** 사용자 B의 화면에서 편집/삭제 UI를 찾으면, **Then** 어떠한 편집·삭제 관련 액션도 노출되지 않는다.

### User Story 4 - 다른 사용자의 공개 문제집 둘러보기 (Priority: P3)

로그인한 사용자는 다른 사용자가 공개한 문제집 목록을 조회하고 그 안의 문제들을 학습/암기 모드로 볼 수 있다. 편집·삭제·복제는 할 수 없다.

**Why this priority**: 있으면 좋은 커뮤니티 기능이지만, 개인 학습만으로도 앱의 가치는 성립한다.

**Independent Test**: 사용자 A가 공개 문제집을 하나 만들어 둔 상태에서 사용자 B로 로그인 → 공개 문제집 목록 확인 → A의 문제집 열기 → 학습 모드로 순회 → 편집/삭제 UI가 노출되지 않음을 확인.

**Acceptance Scenarios**:

1. **Given** 다른 사용자가 만든 공개 문제집이 시스템에 존재할 때, **When** 로그인한 사용자가 공개 문제집 목록을 열면, **Then** 그 문제집이 소유자 이름과 함께 목록에 나타난다.
2. **Given** 다른 사용자의 공개 문제집을 열었을 때, **When** 문제를 순회하면, **Then** 자신의 문제집과 동일하게 학습/암기 모드로 조회 가능하다.
3. **Given** 다른 사용자의 공개 문제집을 보고 있을 때, **When** 화면을 확인하면, **Then** 편집·삭제·문제 추가 관련 UI 요소가 노출되지 않는다.

---

### Edge Cases

- 문제집에 문제가 0개일 때 열면 "이 문제집에 아직 문제가 없습니다" 안내를 표시하고, "다음/이전" 액션은 노출하지 않는다.
- 문제집에 문제가 정확히 1개일 때 "다음"을 누르면 곧바로 "학습 완료" 상태로 넘어간다. "이전"은 처음부터 비활성.
- 첫 문제에서 "이전" 버튼은 비활성 상태이며, 마지막 문제에서 "다음"은 여전히 활성이지만 그 결과는 "학습 완료" 상태다.
- 로그인 세션이 만료된 상태에서 화면을 조작하면 로그인 화면으로 리다이렉트된다.
- 비공개 문제집 URL을 로그아웃 상태에서 접근하면 로그인 화면으로 이동한다 (문제집의 존재 여부를 유출하지 않는다).
- 매우 긴 제목/내용/키워드를 입력하면 저장 전에 길이 상한 초과 사유를 안내한다.
- 키워드 입력란에 콤마·엔터만 있고 실제 텍스트가 없는 항목(예: "TCP,,UDP")이 들어오면 빈 항목은 무시하고 나머지만 저장한다.
- 공개 문제집을 다른 사용자가 열고 있는 동안 소유자가 그 문제집을 비공개로 토글하면, 다른 사용자의 다음 페이지 이동/새로고침 시점부터 접근이 거부된다.
- 사용자가 문제집을 순회 중일 때 다른 탭에서 소유자가 그 문제집(또는 안의 문제)을 삭제하면, 이후의 "다음/이전" 액션은 삭제된 문제를 건너뛰거나 유효하지 않은 상태를 감지해 문제집 목록으로 안내한다.
- 순회 중 모드를 바꾸고 싶은 사용자는 브라우저 뒤로 가기 또는 "목록으로" 액션으로 문제집 목록에 돌아가 다시 열어야 한다 (앱 내 모드 전환 버튼은 존재하지 않는다).
- 동일 사용자가 동시에 여러 브라우저 탭에서 같은 문제집을 열고 각각 다른 문제를 보고 있을 때, 탭 간 진행 위치는 서로 독립적으로 동작한다 (전역 진행 상태 없음).
- 아이디에 사용할 수 없는 문자(공백·특수문자 등)를 포함하면 회원가입이 거부된다.

## Requirements *(mandatory)*

### Functional Requirements

**인증 (US2)**

- **FR-001**: 시스템은 사용자가 아이디와 비밀번호로 신규 계정을 만들 수 있게 해야 한다.
- **FR-002**: 시스템은 이미 사용 중인 아이디의 재사용을 거부하고 그 사유를 사용자에게 표시해야 한다.
- **FR-003**: 시스템은 비밀번호를 평문으로 저장하거나 평문으로 비교해서는 안 된다.
- **FR-004**: 시스템은 올바른 자격 증명에 대해 로그인 세션을 발급해야 한다.
- **FR-005**: 시스템은 잘못된 자격 증명에 대해 어느 필드가 틀렸는지 특정하지 않는 통합 오류 메시지를 반환해야 한다.
- **FR-006**: 로그인한 사용자는 언제든 로그아웃할 수 있어야 하며, 로그아웃 시 세션은 즉시 무효화되어야 한다.
- **FR-007**: 시스템은 인증되지 않은 사용자가 문제집·문제 관련 화면에 접근할 때 로그인 화면으로 리다이렉트해야 한다.

**문제집 · 문제 (US3)**

- **FR-008**: 로그인한 사용자는 문제집을 만들 수 있어야 하며, 각 문제집에는 제목과 공개 여부(공개/비공개) 속성이 있어야 한다.
- **FR-008a**: 소유자는 자신의 문제집의 제목과 공개 여부를 언제든 수정할 수 있어야 한다. 변경은 저장 즉시 반영되어야 하며, 이후 조회부터 새 값이 적용되어야 한다.
- **FR-008b**: 소유자는 자신의 문제집을 삭제할 수 있어야 하며, 삭제 시 그 문제집에 속한 모든 문제도 함께 삭제되어야 한다 (연쇄 삭제).
- **FR-009**: 각 문제집은 정확히 한 명의 소유자를 가진다.
- **FR-010**: 로그인한 사용자는 자신이 소유한 문제집 안에 문제를 추가할 수 있어야 한다. 각 문제는 제목, 내용, 키워드 목록(0개 이상 문자열의 순서 있는 배열)을 가진다.
- **FR-010a**: 키워드 입력 UI는 콤마(,) 또는 엔터(Enter)를 구분자로 인식해 입력 문자열을 개별 키워드로 자동 분리하고, 각 키워드를 뱃지(chip) 형태로 표시해야 한다.
- **FR-010b**: 저장 시점에 한 문제 안의 키워드 목록에서 중복(대소문자·앞뒤 공백 무시 기준으로 동일한 항목)은 제거되어야 하며, 남은 항목의 상대 순서는 사용자가 입력한 순서를 그대로 유지해야 한다.
- **FR-010c**: 키워드는 앞뒤 공백을 제거한 뒤 저장하며, 빈 문자열이 되는 항목은 저장하지 않아야 한다.
- **FR-010d**: 소유자는 자신의 문제집에 속한 문제의 제목·내용·키워드 목록을 언제든 수정할 수 있어야 한다. 변경은 저장 즉시 반영되어야 한다. 문제의 생성 시각(정렬 기준)은 수정에도 변하지 않는다.
- **FR-010e**: 소유자는 자신의 문제집에 속한 문제를 개별적으로 삭제할 수 있어야 한다. 삭제된 문제는 문제집 순회에서 즉시 제외되며, 나머지 문제의 상대 순서는 유지된다.
- **FR-010f**: 소유자가 아닌 사용자는 어떤 문제집이나 문제도 수정·삭제할 수 없어야 한다. 관련 UI 요소는 소유자에게만 노출되고, 서버는 비소유자의 수정·삭제 요청을 거부해야 한다.
- **FR-011**: 각 문제는 정확히 하나의 문제집에 속한다 (문제집 1 : 문제 N 관계).
- **FR-012**: 문제집 내 문제의 표시 순서는 문제가 추가된 시간 오름차순이어야 한다.
- **FR-013**: 시스템은 비공개 문제집의 조회를 소유자에게만 허용해야 한다.
- **FR-014**: 시스템은 공개 문제집의 조회를 로그인한 모든 사용자에게 허용해야 한다.
- **FR-015**: 시스템은 로그인하지 않은 사용자에게는 어떤 문제집·문제 데이터도 노출해서는 안 된다.

**순서대로 조회 · 모드 (US1)**

- **FR-016**: 사용자는 문제집을 열 때 학습 모드 또는 암기 모드 중 하나를 선택하여 진입할 수 있어야 한다. 선택한 모드는 그 조회 세션 동안 고정되며, 순회 도중에는 모드를 전환하는 UI를 노출해서는 안 된다.
- **FR-016a**: 모드를 변경하려는 사용자는 문제집 목록(또는 문제집 상세)로 돌아가 문제집을 다시 열어야 한다. 시스템은 이 흐름 외의 모드 변경 경로를 제공해서는 안 된다.
- **FR-017**: 학습 모드에서는 각 문제의 제목·내용·키워드가 처음부터 함께 표시되어야 한다.
- **FR-018**: 암기 모드에서는 각 문제의 제목만 먼저 표시되고, 사용자가 "내용 보기" 액션을 활성화한 후에야 내용과 키워드가 표시되어야 한다.
- **FR-019**: 사용자는 문제집을 볼 때 한 번에 정확히 한 문제만 화면에 표시되며, "다음"과 "이전" 액션으로 정해진 순서를 따라 앞뒤로 이동할 수 있어야 한다.
- **FR-020**: 사용자가 마지막 문제에서 "다음"을 선택하면 시스템은 "학습 완료" 상태를 표시해야 하며, 첫 문제로 순환해서는 안 된다.
- **FR-020b**: "학습 완료" 상태에는 완료를 알리는 문구만 표시하고, 재학습·목록 이동 등의 별도 액션 버튼을 두지 않는다. 사용자는 상단 네비게이션이나 브라우저 뒤로 가기로 이동한다.
- **FR-020a**: 첫 문제에서는 "이전" 액션이 비활성화 상태로 표시되어야 한다 (이전 문제가 없기 때문).
- **FR-021**: 암기 모드에서 다음 또는 이전 문제로 이동하면 그 문제는 다시 제목만 표시되고 내용·키워드는 숨겨진 상태로 초기화되어야 한다 (이미 봤던 문제로 되돌아가도 마찬가지).
- **FR-022**: 시스템은 사용자의 조회 진행 위치(어느 문제까지 봤는지)를 세션 간에 저장해서는 안 된다. "이어서 하기" 기능은 제공하지 않는다.

**공개 문제집 둘러보기 (US4)**

- **FR-023**: 로그인한 사용자는 다른 사용자가 만든 공개 문제집의 목록을 조회할 수 있어야 하며, 목록에는 각 문제집의 제목과 소유자 식별 정보가 함께 표시되어야 한다.
- **FR-024**: 사용자가 다른 사용자의 공개 문제집을 열었을 때 편집·삭제·문제 추가·복제 관련 UI 요소는 노출되지 않아야 한다.

**UI · 범위 제약**

- **FR-025**: 애플리케이션 화면에는 footer 영역을 두지 않는다.

### Key Entities

- **User (사용자)**: 시스템을 사용하는 개인. 아이디, 안전하게 저장된 비밀번호 정보, 계정 생성 시각을 갖는다.
- **Question Set (문제집)**: 사용자가 만든 문제들의 묶음. 제목, 공개 여부(public/private), 소유자, 생성 시각. 소유자 1명, 문제 N개.
- **Question (문제)**: 문제집 안의 한 항목. 제목, 내용, 키워드 목록(순서 있는 문자열 배열, 0개 이상), 소속 문제집, 생성 시각(정렬 기준).
- **Keyword (키워드)**: 문제에 종속된 부속 값. 문자열이며, 문제 레코드 안에 순서 있는 배열의 원소로 저장된다 (별도 엔티티/테이블로 분리하지 않음). 문제와 함께 저장되고 독립적으로 존재하지 않는다.
- **Session (세션)**: 로그인된 사용자의 인증 상태. 로그인 시 발급되고 로그아웃 또는 만료 시 무효화된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 로그인 후 문제집 하나를 열고 첫 문제가 화면에 보이기까지 5초 이내에 완료된다.
- **SC-002**: 학습 모드와 암기 모드를 각각 사용한 사용자의 90% 이상이 첫 사용 시 추가 안내 없이 두 모드의 차이를 이해한다.
- **SC-003**: 사용자가 회원가입부터 자신의 첫 문제집(문제 3개 포함)을 만들어 학습을 시작하기까지 걸리는 시간이 5분 이내이다.
- **SC-004**: 비공개 문제집이 소유자가 아닌 사용자에게 노출되는 사례가 0건이다.
- **SC-005**: 로그인하지 않은 사용자가 문제집·문제 콘텐츠에 접근하는 사례가 0건이다.
- **SC-006**: 문제 조회 중 "다음" 액션을 취했을 때 다음 문제가 화면에 나타나기까지 1초 이내이다.
- **SC-007**: 100문제 이하의 문제집을 처음부터 끝까지 순회할 때 시스템이 지연 없이 안정적으로 동작한다.

## Assumptions

- 인증은 아이디(username) 기반만 사용한다. 이메일·전화번호·OAuth·비밀번호 재설정 흐름은 이 스펙 범위 밖이다.
- 문제의 표시 순서는 생성 시각 오름차순을 기본으로 한다. 사용자가 순서를 임의로 재정렬하는 기능은 이 스펙 범위 밖이다 (수정은 필드값만 변경하며 정렬 기준인 생성 시각은 유지된다).
- 공개 문제집을 다른 사용자가 복제·포크하는 기능은 없다. 조회만 가능하다.
- 사용자가 조회 도중 앱을 벗어나더라도 진행 위치를 저장하지 않는다. 다시 열면 항상 첫 문제부터 시작한다 ("이어서 하기" 없음, 사용자 명시).
- 화면 하단 footer 영역은 두지 않는다 (사용자 명시).
- 사용자 인터페이스 언어와 오류 메시지는 한국어를 기본으로 한다.
- 아이디는 대소문자를 구분하지 않고 유일하게 취급한다.
- 비밀번호는 최소 8자 이상을 요구한다 (일반적 웹앱 관행).
- 한 문제집에 담을 수 있는 문제 수와 한 사용자가 만들 수 있는 문제집 수에는 명시적 상한을 두지 않으나, 첫 릴리스는 문제집당 100문제 이내에서 원활히 동작하는 것을 목표로 한다.
- 이 스펙 범위에서는 관리자 역할·권한 구분이 없다. 모든 로그인 사용자는 동등한 권한을 가진다.
